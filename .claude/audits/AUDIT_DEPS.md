# Dependency Audit — Stock & Spoon

## Summary
Root project (`npm audit`): **30 vulnerabilities** (22 high, 8 moderate) across 1,264 resolved packages (262 prod / 1,002 dev / 175 optional). All flagged root vulns trace to **dev-only** chains (eslint 9 toolchain, `vite-plugin-pwa`→workbox, `puppeteer-extra-plugin-stealth`, `react-router-dom`→`react-router`) — no prod-dependency vuln paths reach the shipped bundle.

`functions/` subproject (separate `npm audit`): **51 vulnerabilities (3 critical, 12 high, 34 moderate, 2 low)** across 845 resolved packages, and these run in production Cloud Functions (via `firebase-admin`, `googleapis`, `nodemailer`, `@aws-sdk/*` transitive from mailer/GCS deps). This is the higher-severity half of the audit.

Unused dependencies confirmed by grep: `react-router-dom` (root, already flagged in CLAUDE.md as installed-but-unused for navigation — only referenced from test files), `adb` (root prod dep, zero references in source), and `stripe` + `@paypal/paypal-server-sdk` + `@paypal/react-paypal-js` (all three declared in `functions/package.json` but zero references anywhere under `functions/src` — the actual IAP path is `cordova-plugin-purchase`/Google Play Billing per `verifyPurchase.ts`, per CLAUDE.md).

Notable version skew between the two package.json files that maintain the same tooling independently: `firebase-admin` (root devDependency `^14.1.0` vs `functions` `^12.1.0`, audit recommends `14.2.0`), `eslint` (root `^9.21.0` vs `functions` `^8.9.0`), `typescript` (root `^6.0.3` vs `functions` `^4.9.5`), `@types/nodemailer` (root `^8.0.1` vs `functions` `^6.4.15`).

## Findings

- **HIGH** — `functions/package.json` (prod deps, transitive) — `protobufjs <=7.6.4` pulled in via `googleapis`/`@google-cloud` chain has a **critical** severity advisory (prototype pollution class); no direct override, needs upstream `googleapis` bump. Remediation: `cd functions && npm audit fix`, and if unresolved, bump `googleapis` to `^173.0.0` (major, breaking) or pin `protobufjs` via `overrides`.
- **CRITICAL** — `functions/package.json:23` (`nodemailer": "^6.10.1"`) — resolves to a vulnerable `<=9.0.0` range per audit (also drags in vulnerable `form-data`); fix available at `nodemailer@9.0.3` but is a major bump. Remediation: upgrade `nodemailer` to `^9.0.3`, retest email flows (`services/` mailer usage, `functions/src` invite emails).
- **CRITICAL** — `functions/package.json` (transitive via `@google-cloud/storage`/`@aws-sdk/client-ses`) — `fast-xml-parser <=5.6.0` and `websocket-driver <=0.7.4` both carry critical advisories with no direct fix path listed (`fixAvailable: true` but only via full dependency-tree resatisfaction, not a simple bump). Remediation: `npm audit fix` in `functions/`, verify no functionality regresses in nodemailer/GCS calls, re-run `npm audit`.
- **MODERATE** — `functions/package.json:20` (`firebase-admin": "^12.1.0"`) — audit flags `10.2.0–13.10.0` range vulnerable via `@google-cloud/storage`→`retry-request`/`teeny-request`→`uuid` chain; fix requires `firebase-admin@14.2.0` (major). Root's own `devDependencies` already pin `firebase-admin@^14.1.0` — aligning both to the same major would close this and remove the skew noted above. Remediation: bump `functions/package.json` `firebase-admin` to `^14.2.0`, run functions test suite.
- **MODERATE** — `functions/package.json:22` (`googleapis": "^144.0.0"`) — audit range `33.0.0–149.0.0` vulnerable (chain includes the critical `protobufjs`/`fast-xml-parser` issues above); fix at `googleapis@173.0.0` is a major bump touching every generated client shape used in `functions/src`. Remediation: schedule as a dedicated upgrade task, not a drive-by bump — audit call sites first.
- **HIGH** — `package.json` (root, dev-only) — `eslint@^9.21.0` and its `@eslint/config-array`/`@eslint/eslintrc`/`minimatch`/`brace-expansion` chain are all flagged high via a shared `minimatch` ReDoS-class range; fix is `eslint@10.8.0` (major, dev tooling only — no prod impact). Remediation: bump eslint major when convenient, re-run lint config migration.
- **HIGH** — `package.json:134` (`vite-plugin-pwa": "^1.3.0"`, dev-only) — pulls vulnerable `workbox-build`→`jake`→`ejs`/`filelist` chain (`@trickfilm400/rollup-plugin-off-main-thread <=3.1.0-pre2`); fix listed as `vite-plugin-pwa@1.2.0`, i.e. audit is pointing at a *downgrade* target that predates the currently-pinned `^1.3.0` — likely audit metadata lag; verify current `vite-plugin-pwa` release notes before acting, don't blindly downgrade.
- **HIGH** — `package.json:122-124` (`puppeteer-extra": "^3.3.6"`, `puppeteer-extra-plugin-stealth": "^2.11.2"`, dev-only, used only by `scripts/scrape-allrecipes.js`) — vulnerable `rimraf`/`glob`/`google-gax` chain via `puppeteer-extra-plugin-user-preferences`. Dev/script-only blast radius. Remediation: low priority; bump when the scraping script is next touched, or drop the `puppeteer-extra*` stealth plugins entirely if `scrape-allrecipes.js` is no longer in active use.
- **LOW/UNUSED** — `package.json:78` (`"adb": "^0.2.0"`) — zero references found anywhere in the codebase (`grep` for `require('adb')`/`from 'adb'` returns nothing); appears to be a stray/leftover prod dependency (possibly meant to be a dev tool, not a runtime dep — ships in the bundle graph unnecessarily since it's not in `devDependencies`). Remediation: remove, or move to `devDependencies` if it's actually used for some ADB automation step not caught by static grep.
- **LOW/UNUSED** — `package.json:125` (`react-router-dom": "^7.18.1"`, devDependency) + transitive `react-router` — CLAUDE.md itself documents "no router... dependency but unused for navigation"; grep confirms the only references are in `src/test/smoke-all-components*.test.tsx` and `src/test/test-utils.tsx` (test scaffolding), not app code. Also the source of two of the root's high-severity findings (`react-router`/`react-router-dom` fix-available entries). Remediation: if the test scaffolding doesn't need it either, remove entirely; otherwise keep pinned but note it no longer needs security triage beyond test infra.
- **LOW/UNUSED** — `functions/package.json:18-19,24` (`@paypal/paypal-server-sdk": "^2.1.0"`, `@paypal/react-paypal-js": "^8.9.2"`, `stripe": "^20.0.0"`) — zero matches for `paypal`/`stripe` anywhere under `functions/src` (only appear in `functions/package.json`/`functions/package-lock.json`). CLAUDE.md documents the actual IAP path as `cordova-plugin-purchase` + Google Play Billing (`verifyPurchase.ts`). These three appear to be dead/leftover dependencies (possibly from an abandoned web-payment path) inflating the Cloud Functions deploy bundle and the vulnerability surface (`stripe@^20.0.0` itself pulls no listed vulns currently, but `@paypal/react-paypal-js` is a *frontend* React package with no business being in a Cloud Functions `dependencies` block at all). Remediation: confirm with product whether PayPal/Stripe billing is planned/deprecated; if dead, remove from `functions/package.json` and re-lock.
