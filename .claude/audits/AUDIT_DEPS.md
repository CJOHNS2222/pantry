# Dependency Audit - Stock and Spoon

## Summary
Since the previous audit, the two highest-severity vulnerability chains have been resolved: root npm audit dropped from 30 vulnerabilities (22 high / 8 moderate) to 7 moderate / 0 high / 0 critical, and functions/ npm audit dropped from 51 (3 critical / 12 high / 34 moderate / 2 low) to 9 moderate / 0 high / 0 critical.
The previously-flagged unused deps (react-router-dom, adb in root; stripe, @paypal/paypal-server-sdk, @paypal/react-paypal-js in functions/) have all been removed from both package.json files - confirmed via grep, none remain. The firebase-admin/eslint cross-package major-version skew is mostly closed (firebase-admin now ^14.2.0 in both root devDependencies and functions/package.json), except typescript still differs (root ^6.0.3 vs functions ^5.7.3).
functions/ also has an unresolved peer-dependency inconsistency: firebase-functions-test@3.5.0 declares a peer range on firebase-admin of ^8.0.0 through ^13.0.0, but the installed firebase-admin@14.2.0 does not satisfy it - npm ls reports ELSPROBLEMS/invalid for this pairing. Root-level npm install still requires --legacy-peer-deps (documented in CLAUDE.md) because @codetrix-studio/capacitor-google-auth@3.4.0-rc.4 declares peerDependencies: { "@capacitor/core": "^6.0.0" } while the rest of the Capacitor stack is pinned to ^8.x - confirmed directly from the installed package own package.json.
Outdated-but-not-vulnerable: root has 26 outdated packages (5 with major-version gaps: eslint 9 to 10, typescript 6 to 7, jsdom 29 to 30, react-window 1 to 2, @testing-library/jest-dom 6 to 7); functions/ has 3 (eslint 9 to 10, typescript 5.9 to 7, globals minor). No unused-dependency findings beyond what has already been cleaned up - a targeted grep for lower-confidence deps (@emailjs/browser, capacitor-plugin-safe-area, @ebarooni/capacitor-calendar, zod, fuse.js, tesseract.js, @zxing/library, cordova-plugin-purchase) confirmed live usage for all of them.

## Findings

- **MODERATE** - root package.json (prod chain) + functions/package.json (prod) - firebase-admin@14.2.0 -> @google-cloud/storage@7.21.0 pins gaxios@6.7.1 / teeny-request@9.0.0 / retry-request@7.0.x, all flagged moderate via a nested uuid@9.0.1 "missing buffer bounds check" advisory (7 duplicate audit entries per package.json, same root cause). npm audit auto-fix suggests downgrading to firebase-admin@10.3.0 - do not apply, that is a 4-major-version regression that would break functions/src call sites built against the v14 API surface. Remediation: track upstream @google-cloud/storage / firebase-admin releases for a gaxios/uuid bump; re-run npm audit after each firebase-admin update rather than forcing a downgrade now.
- **MODERATE** - `functions/package.json:27` (firebase-functions-test pinned "^3.1.0", resolves to 3.5.0) - pulls ts-deepmerge@2.0.7 which resolves below the fixed 8.0.0 line per audit (prototype-method-override DoS advisory); fixAvailable points at a downgrade to firebase-functions-test@0.3.3 (major regression, not viable). Dev/test-only blast radius (used only in Cloud Functions emulator test harness). Remediation: low priority, revisit when firebase-functions-test next majors past its own ts-deepmerge pin.
- **WARN/PEER-CONFLICT** - `functions/package.json` - npm ls reports ELSPROBLEMS: firebase-functions-test@3.5.0 (and firebase-functions@7.3.2) declare a peer range on firebase-admin of ^8.0.0 through ^13.0.0, but the installed firebase-admin@14.2.0 does not satisfy it (shows invalid). Currently silent because functions/ installs succeed without --legacy-peer-deps enforcement failing the build, but it is a real version mismatch that could surface as a runtime API shape difference in the test harness. Remediation: confirm firebase-functions-test has a release supporting firebase-admin@14.x, or pin the test harness to a compatible firebase-admin range in a separate check; track for the next Functions dependency bump.
- **INFO/PEER-CONFLICT (pre-existing, documented)** - `package.json:72` (@codetrix-studio/capacitor-google-auth pinned "^3.4.0-rc.4") - declares peerDependencies: { "@capacitor/core": "^6.0.0" } (confirmed from the installed package own package.json) against the project @capacitor/core@^8.4.1, a two-major-version gap. This is the specific cause of the --legacy-peer-deps requirement documented in CLAUDE.md. The package itself is still on an -rc prerelease tag with no newer release targeting Capacitor 8/9. Remediation: no drop-in fix currently exists; either keep --legacy-peer-deps as the documented workaround (status quo, low risk since the Google Auth plugin functions correctly in testing) or evaluate migrating to @capacitor-firebase/authentication Google provider (already using @capacitor-firebase/* for analytics/crashlytics) to drop this stale peer dependency entirely.
- **OUTDATED (major)** - root package.json devDependencies - eslint 9.39.5 -> 10.8.0, typescript 6.0.3 -> 7.0.2, jsdom 29.1.1 -> 30.0.1, react-window 1.8.11 -> 2.3.0, @testing-library/jest-dom 6.9.1 -> 7.0.0 are all a major version behind. All dev/test-tooling except react-window (prod, virtualized list rendering - used in pantry/recipe list views); a react-window v2 major bump changes its API surface (moved to a hooks-based API) and would need call-site updates, not a drive-by bump. Remediation: schedule eslint/typescript major bumps together (shared plugin ecosystem via typescript-eslint@8.64.0, itself one minor behind at 8.65.0), verify type-check/lint scripts after; treat react-window v2 as its own scoped task.
- **OUTDATED (skew)** - root package.json typescript pinned "^6.0.3" vs functions/package.json typescript pinned "^5.7.3" (resolves 5.9.3) - the two TypeScript projects are still one major apart (root TS6 vs functions TS5), unlike firebase-admin/eslint which were aligned since the last audit. Remediation: bump functions/package.json typescript to match root major when convenient - low urgency since functions/ is a fully separate tsconfig.json/build, but worth closing to avoid divergent language-feature availability between the two TS projects.
- **OUTDATED (minor/patch, batchable)** - root package.json - 21 further packages are behind on minor/patch only (no breaking-change risk expected): @capacitor/android 8.4.2->8.5.0, @capacitor/camera 8.2.1->8.2.2, @capacitor/cli 8.4.2->8.5.0, @capacitor/core 8.4.2->8.5.0, @google/genai 2.12.0->2.15.0, @playwright/test 1.61.1->1.62.1, @sentry/react 10.66.0->10.69.0, @types/node 26.1.1->26.1.2, @types/react-dom 19.2.3->19.2.4, @vitejs/plugin-react 6.0.3->6.0.5, firebase 12.16.0->12.17.0, globals 17.7.0->17.9.0, lint-staged 17.0.8->17.3.0, lucide-react 1.25.0->1.28.0, postcss 8.5.19->8.5.25, react/react-dom 19.2.7->19.2.8, react-intl 10.1.18->10.1.20, typescript-eslint 8.64.0->8.65.0, vite 8.1.5->8.2.0, vite-plugin-checker 0.14.4->0.14.5. Remediation: safe to batch-bump in one PR (npm update within existing semver ranges covers most since these are already caret-pinned) - verify each wanted vs latest before assuming zero-risk on the handful that differ.
